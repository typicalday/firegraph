## 1. Goal

Give firegraph a registry-driven way for each record type (`aType`) to declare which `data` fields are full-text-searchable on the local SQLite FTS backends (`firegraph/sqlite-local` = better-sqlite3, `firegraph/sqlite-builtin` = node:sqlite). A declaration produces, per declaring `aType`:

1. a per-type FTS5 partition table containing ONLY text extracted from the declared fields, and
2. per-type BM25 ranking: a `fullTextSearch()` filtered to that single `aType` is scored against that partition's own corpus, not against the shared mixed table.

Simultaneously, remove the trigger-name collision PR #37 introduced: the three shared FTS triggers (`<t>_fts_ai` / `<t>_fts_au` / `<t>_fts_ad`) must NEVER again be `DROP`ped + re-`CREATE`d by firegraph, so a consumer that customizes them through the public `extraTableDDL` hook (the preemption pattern: consumer DDL runs first, firegraph's `CREATE TRIGGER IF NOT EXISTS` then no-ops) keeps working in every configuration.

Non-goals: no engram changes; no npm publish/manual version bump (release-please handles versioning from conventional commits); no query-time `fields` support (`fullTextSearch({ fields })` stays rejected with `INVALID_QUERY` on all backends); no Firestore behavior change.

## 2. Architecture decisions (the load-bearing choices)

### 2.1 Shared index is frozen; per-type behavior lives in separately-named artifacts

- `buildFtsDDL` (src/internal/sqlite-search.ts, currently lines 176–264) REVERTS to its pre-PR-#37 shape: no `perTypeFtsStats` parameter, always emits `CREATE TRIGGER IF NOT EXISTS` for the three shared triggers, with bodies byte-identical to today's empty-config path (which is byte-identical to pre-#37). The shared `<t>_fts` continues to index ALL text leaves of every row (`textExtractionExpr` with no field filter). This makes the no-opt-in path byte-identical (success criterion 3) and makes coexistence structural (criterion 4): firegraph never fights over the shared trigger names again.
- Per-type maintenance moves out of the shared trigger bodies into three NEW, firegraph-owned, per-`aType` triggers (section 2.4). Their names are namespaced under the partition-table name, so firegraph may freely `DROP TRIGGER IF EXISTS` + `CREATE TRIGGER` them on every bootstrap (deterministic reconciliation to the current field list) without touching anything a consumer owns.
- Consequence, to document explicitly: a cross-type search (no `aType` filter) still runs against the shared all-text index — junk-field pollution is fixed only on the per-type search path. That is the honest scope of this feature; say so in the docs.

### 2.2 Public API: `IndexSpec.fullText`

In `src/types.ts`, next to `IndexSpec.vector` (line 245):

```ts
export interface IndexSpec {
  fields: Array<string | IndexFieldSpec>;
  where?: string;
  vector?: { field: string; dimension: number };
  /**
   * Full-text searchable-field declaration for the local SQLite backends
   * (firegraph/sqlite-local, firegraph/sqlite-builtin). `fields` (inside
   * this object) is a NON-EMPTY list of bare data-relative field paths
   * (e.g. 'title', 'nested.summary') — the only fields whose text is
   * indexed into the declaring aType's per-type FTS partition, which also
   * isolates that type's BM25 statistics. Ignored by every other backend
   * (Firestore both editions, D1, Cloudflare DO). A fullText spec carries
   * an empty outer `fields: []` — it does not create a composite index.
   */
  fullText?: { fields: string[] };
}
```

Collection rules — new `collectFullTextDeclarations(registry)` in `src/internal/sqlite-search.ts`, modeled on `collectVectorDeclarations` (lines 977–1001):

- Each declared field path: split on `.`, validate every segment with `validateJsonPathKey` (same rule as `vectorShadowColumn`). Invalid → `FiregraphError` code `INVALID_ARGUMENT` at factory time (fail fast).
- `fullText.fields` empty → `INVALID_ARGUMENT` ("declare at least one field; for all-fields per-type stats use the perTypeFtsStats backend option").
- Multiple registry entries sharing one `aType` (node entry + edge entries — the partition keys on `a_type` alone, so every row with that `a_type` lands in it regardless of `axbType`): UNION the field lists, dedupe, sort for determinism. Document the union rule on the type.
- Returns a deterministic `ReadonlyMap<string /* aType */, readonly string[] /* sorted fields */>`.

### 2.4 Per-type DDL: partition tables + three firegraph-owned triggers per declared type

New builders in `src/internal/sqlite-search.ts` (replacing the folding code inside `buildFtsDDL` / `buildFtsSyncStatements`):

- `perTypeFtsTableName(table, aType)` — KEEP as-is (line 121: `${table}_fts_t_${mangleStorageScope(aType)}`; the `_fts_t_` infix rationale in its doc comment stays valid and load-bearing).
- Trigger names, one set per declared aType: `<partitionTableName>_ai`, `<partitionTableName>_au`, `<partitionTableName>_bd`. (`mangleStorageScope` is injective, so distinct aTypes never collide; SQLite triggers live in their own name namespace, so collision with table names is impossible.)
- `textExtractionExpr(dataRef, fields?: readonly string[])` — extend the existing helper (line 135). `fields` undefined → current all-text expression, byte-identical output. Non-empty → field-filtered pure SQL, evaluatable inside triggers from any connection (preserves the any-connection invariant):

```sql
(SELECT coalesce(group_concat("value", ' '), '') FROM (
  SELECT "value" FROM json_tree(coalesce(<dataRef>, '{}'), '$.<f1>') WHERE "type" = 'text'
  UNION ALL
  SELECT "value" FROM json_tree(coalesce(<dataRef>, '{}'), '$.<f2>') WHERE "type" = 'text'
))
```

Each `$.<field>` path is inlined — injection-safe because every segment passed `validateJsonPathKey` (same argument as `vectorBackfillSelectSql`, line 943). `json_tree` with a path argument returns zero rows for a missing path (no error), returns the leaf itself when the path points at a string, and walks a subtree when it points at an object/array — so a declared field may be a scalar or a subtree, and non-text leaves (numbers, booleans, numeric timestamps) are excluded by `"type" = 'text'`.

- `buildPerTypeFtsDDL(table, config: PerTypeFtsConfig): string[]`:
  - per aType: `CREATE VIRTUAL TABLE IF NOT EXISTS <ptfts> USING fts5("text")` (single `text` column — same shape as the shared index; per-field FTS5 columns are deliberately deferred; note them as future work that would enable query-time `fields`).
  - per aType, three triggers emitted as `DROP TRIGGER IF EXISTS <name>` + `CREATE TRIGGER <name> ...` (unconditional recreate is CORRECT here — these names are firegraph-owned and the body depends on the declared field list; recreating reconciles a changed field list deterministically on every bootstrap; the DROP+CREATE pair is idempotent):
    - `_ai` — `AFTER INSERT ON <t>`: (1) the conflict-free map-ensure `INSERT INTO <map> ("doc_id") SELECT new."doc_id" WHERE NOT EXISTS (...)` — the SAME statement text the shared AI trigger uses (line 187; the WHERE-NOT-EXISTS form, NOT `INSERT OR IGNORE`, for the upsert-conflict-algorithm reason documented there); (2) `DELETE FROM <ptfts> WHERE rowid = <mappedId>`; (3) `INSERT INTO <ptfts> (rowid, "text") SELECT <mappedId>, <textExtractionExpr(new."data", fields)> WHERE new."a_type" = '<escaped aType>'` (reuse `escapeSqlLiteral`).
    - `_au` — `AFTER UPDATE ON <t>`: same body as `_ai` (unconditional delete + guarded insert handles a row whose `a_type` changes on update: it leaves the partition it no longer belongs to and enters the one it now does).
    - `_bd` — `BEFORE DELETE ON <t>`: `DELETE FROM <ptfts> WHERE rowid = (SELECT "id" FROM <map> WHERE "doc_id" = old."doc_id")`.
  - WHY this is race-free where PR #37's comments claim separate triggers cannot be (rewrite the "folding is required" rationale at lines 159–174 accordingly): (a) INSERT/UPDATE side — SQLite does not guarantee inter-trigger firing order, so a per-type trigger must not rely on the shared AI/AU having created the map row first; carrying its OWN idempotent map-ensure statement makes it order-independent (whichever trigger fires first creates the map row; the other's ensure no-ops). (b) DELETE side — the shared `_ad` is an AFTER DELETE trigger whose last statement removes the map row; a per-type AFTER DELETE would race it. A per-type BEFORE DELETE fires before the row deletion and before ANY after-trigger, when the map row is still guaranteed present. No folding needed, so the shared trigger bodies never change.
- `buildPerTypeFtsSyncStatements(table, config): string[]` — adapt the existing per-type block of `buildFtsSyncStatements` (lines 297–321): per aType, purge ghosts (`doc_id` gone OR `a_type` mismatch) then insert missing rows using the field-filtered extraction. Runs after the shared sync statements so map rows exist. Note: sync statements only fix MISSING/GHOST rowids; rows whose stored text predates a field-list change are handled by the fingerprint rebuild (2.5).
- `buildFtsSyncStatements(table)` loses its `perTypeFtsStats` parameter (reverts to shared-only, lines 278–296).
- `buildLocalSearchDDL(table, config)` composes: shared FTS DDL (frozen) → per-type table+trigger DDL → shared sync → per-type sync. All statements remain idempotent as `extraTableDDL` requires.
- `findOrphanedFtsTables` (line 1054): change the 4th parameter from `perTypeFtsStats: readonly string[]` to the configured aType list derived from the unified config keys (two-pass suffix logic and its doc comment stay).

### 2.5 Bootstrap-time JS ensure step (`ftsEnsure`) — config fingerprint + legacy-0.19.0 healing

Pure DDL strings cannot make read-dependent decisions, so each search-wrapper backend instance (root and every subgraph wrapper — mirror the `vecEnsured` lazy-promise pattern in `wrapLocalSearchBackend`, src/sqlite/local.ts lines 292–399) gets a cached `ftsEnsured` promise, awaited by `fullTextSearch` before compiling, and reset to null on the self-heal path (alongside `inner.ensureReady(true)`). Steps, in order, all tolerant of read-only handles via the existing `isReadonlyWriteError` pattern (skip writes, proceed):

1. `await inner.ensureReady()` (extraTableDDL — including per-type partitions, triggers, and sync — has run).
2. LEGACY FOLDED-TRIGGER RESET (heals DBs written by 0.19.0 with `perTypeFtsStats` opted in): `SELECT "name", "sql" FROM sqlite_master WHERE "type" = 'trigger' AND "tbl_name" = '<table>' AND "name" IN ('<t>_fts_ai', '<t>_fts_au', '<t>_fts_ad')`. For each whose `sql` contains the substring `_fts_t_` (the firegraph per-type infix — the folded-body signature; a consumer's own customization does not reference firegraph partition tables): `DROP TRIGGER` it, then re-run that trigger's canonical `CREATE TRIGGER IF NOT EXISTS` statement from `buildFtsDDL`. Triggers WITHOUT the signature are NEVER touched — that is precisely the customization-preservation guarantee. Document the detection rule and its assumption in a comment.
   - Why bother even though double-maintenance is content-identical for all-text partitions: it stops double trigger work per write, and it un-clobbers any consumer customization that 0.19.0 destroyed (their extraTableDDL re-installs it on their next bootstrap once firegraph stops recreating folded triggers).
3. STALE PER-TYPE TRIGGER CLEANUP (handles a de-configured aType): `SELECT "name" FROM sqlite_master WHERE "type" = 'trigger' AND "tbl_name" = '<table>' AND "name" GLOB '<t>_fts_t_*'` — use GLOB, not LIKE (table names contain `_`, a LIKE wildcard). Drop any name not in the current config's expected per-type trigger-name set. The de-configured type's PARTITION TABLE is left in place, stale; document that it is now safe to `DROP TABLE` manually in EVERY scenario — this replaces the Scenario A/B caveat on `perTypeFtsStats` (src/sqlite/backend.ts lines 131–159), which MUST be rewritten.
4. CONFIG FINGERPRINT / REBUILD, only when the unified config is non-empty: `CREATE TABLE IF NOT EXISTS <rootTable>_fts_cfg ("table_name" TEXT NOT NULL, "a_type" TEXT NOT NULL, "cfg" TEXT NOT NULL, PRIMARY KEY ("table_name", "a_type"))`. Per configured aType: canonical `cfg` JSON is `{"fields":null}` or `{"fields":[...sorted]}`. If the stored row is missing or differs: `DELETE FROM <ptfts>` (full purge), re-run that aType's per-type sync statements (backfill with current extraction), upsert the cfg row. Delete cfg rows for aTypes no longer configured for this table. HARD CONSTRAINT (byte-identical no-opt-in): when the unified config is EMPTY, the `_fts_cfg` table is NEVER created and steps 3–4 issue no writes — a no-opt-in database's schema artifacts must be exactly today's set (step 2's read + conditional heal is still allowed; it writes nothing on a clean DB).
5. The cascade orphan sweep (`sweepOrphanedFtsArtifacts`, local.ts lines 225–244) additionally deletes `_fts_cfg` rows whose `table_name` was swept (tolerate a missing cfg table).

Timing justification (write-path safety WITHOUT gating writes): per-type triggers are installed/reconciled by extraTableDDL at inner bootstrap, i.e. before any write through this backend. A 0.19.0 DB's legacy folded triggers coexisting with the new per-type triggers until first search is benign for legacy-configured types: both maintenance paths write identical all-text content, so trigger execution order does not matter. Registry-vs-legacy conflicts are rejected at factory time, so a folded all-text body and a field-filtered new body can only disagree if a declaration changed across versions — and the fingerprint rebuild restores partition content deterministically before the first search ranks against it. Therefore only `fullTextSearch` awaits `ftsEnsure`; write methods stay pass-through.

## 4. Edge cases the implementation must handle

1. Row of a declared type where NO declared field is present → indexed into the partition with empty text (matches nothing). Deliberate: keeps the backfill's "insert missing rowids" idempotent (skipping empties would re-attempt every bootstrap) and matches PR #37's all-rows-of-the-type semantics.
2. Declared field holding a number/bool (e.g. a numeric timestamp) → excluded by `"type" = 'text'`; a subtree field indexes only its text leaves; a missing path contributes nothing (json_tree returns zero rows, no error).
3. Upsert (`INSERT … ON CONFLICT DO UPDATE`): the INSERT arm fires `_ai`, the conflict arm fires `_au`; both bodies start with the defensive partition delete → no double-indexing. The map-ensure MUST use the `WHERE NOT EXISTS` form (conflict-algorithm comment at sqlite-search.ts line 182 applies to per-type triggers too).
4. A DELETE that aborts after `_bd` ran would leave the partition row missing while the base row survives — healed by the next bootstrap's per-type sync backfill. Accepted (no FK constraints exist here; abort-after-before-trigger paths are exotic).
5. Read-only DB handle: `ftsEnsure` swallows readonly-write errors and searches whatever is materialized (mirror `ensureReadyTolerant`, local.ts lines 346–352).
6. aType strings needing SQL-literal escaping (`escapeSqlLiteral`) and name mangling (`mangleStorageScope`) — reuse both helpers verbatim; GLOB (not LIKE) for the stale-trigger scan, and constrain that scan by `tbl_name` so another graph table's triggers are never touched.
7. `where` filters combined with a declared-type search: filters compile against the joined base table exactly as today; only the MATCH table differs.
8. Dynamic-registry mode: `collectFullTextDeclarations` runs once at factory time against `options.registry` — same snapshot semantics as `collectVectorDeclarations`. Types added to a dynamic registry later do not get partitions until the backend is reconstructed; document, do not engineer around.

## 6. Assumptions decided here (routine ambiguity, not escalated)

- Auto-routing default-on for configured types (`perTypeStats` becomes opt-out) — a behavior change vs the one-day-old 0.19.0, judged safe and strictly better; documented in changelog and docs.
- Shared-index content stays all-text for declared types (cross-type searches unchanged); field filtering applies on the per-type path only. This is what keeps the shared triggers frozen and coexistence structural rather than best-effort.
